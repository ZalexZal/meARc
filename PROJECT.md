## 1. What the app is

An augmented reality mobile app in Unity. You point your phone at a building and a
geo-anchored marker appears on it. Tapping the marker opens a bottom sheet with the
building's name, year, architect, type, description and an external link.

- **Audience** — general public and architecture students; secondarily tourists,
  urban planners, historians.
- **Platform** — Android is the active target. iOS is possible but **needs a Mac**;
  Unity cannot compile for iOS on Windows.
- **Scale** — 100+ buildings at launch, city-wide, starting in Yambol, Bulgaria.
  Long-term: other cities.
- **Languages** — Bulgarian and English, both at launch.
- **Budget** — free/open-source preferred; a few euros acceptable for a clearly
  justified tool.
- **App name** — still undecided. Do not invent one.

The defining constraint, and the reason the architecture looks the way it does:
**adding a building must not require a rebuild.** Content lives in a Google Sheet,
markers are created at runtime from coordinates, and neither Unity nor the Play Store
is involved in publishing a new building.

## 3. Honest status

### Proven on a real device
- App launches, camera passthrough renders, permissions are requested.
- The three-tab UI works: Camera, Search, Settings.
- **Building data loads from the Google Sheet over the network** and renders on the
  phone — verified by screenshot, with Cyrillic, categories, eras, distances and the
  discovery counter all correct.
- Bulgarian text renders correctly (see §13 for why this turned out not to be a
  problem after all).
- **Markers appear on their real buildings.** Both sheet rows resolved as terrain
  anchors and landed in the correct places outdoors. This confirms the whole chain at
  once: sheet coordinates → runtime spawning → `ResolveAnchorOnTerrainAsync` →
  correct world placement. It also retrospectively validates the two decisions that
  cost the most debugging — moving coordinates into the sheet, and switching from
  WGS84 to terrain anchors.

### Built but never confirmed on a device
- **Occlusion** (`OcclusionService`). It was written *after* the successful field
  test, so that build did not contain it. Streetscape Geometry coverage in Yambol
  is still unknown — see §13 for how to check in two minutes.
- **Tapping a spawned marker** to open its info sheet. The tap chain is proven in the
  Editor and `CubeTapManager` is unchanged, but the combination of a runtime-spawned
  marker and an on-device tap has not been exercised.
- Marker distance scaling and the release radius, in practice, with more than two
  buildings in range.
- The GPS fallback tier and the VPS coverage check — written but not yet taken
  outdoors or indoors.

### Not started
- Content. Two placeholder rows exist in the sheet.
- Store listing, signing, privacy policy.
- Notification scheduling, onboarding tutorial, marker visual design.

## 5. Architecture

```
Google Sheet  ──published CSV──▶  RemoteBuildingSource
                                        │  fetch → parse → cache
                                        ▼
                                 BuildingDatabase
                    (buildings from sheet · categories & eras from Resources)
                       │              │                │
                       ▼              ▼                ▼
                  Search tab    Nearby / Ready    MarkerSpawner
                                                        │
                                                 terrain anchors
                                                        ▼
                                                  AR markers ──▶ OcclusionService
```

**The key design move:** `BuildingData` is a `ScriptableObject`, and ScriptableObjects
can be created at runtime with `CreateInstance` — they simply are not saved as assets.
So the remote layer parses a CSV row, builds a `BuildingData` in memory, and hands it
to exactly the same UI code that used to read assets from `Resources`. **The entire UI
was untouched by the move to remote content.**

Everything lives on one always-active GameObject called **`AppServices`**, created by
the build tool: `AppLifecycleWatcher`, `RemoteBuildingSource`, `UserLocationService`,
`MarkerSpawner`, and `OcclusionService`. It is always active because the Camera tab is
disabled whenever the reader is on another tab, and several of these must keep running
regardless.

## 6. The content pipeline

### The sheet

Published to the web as CSV. The URL is baked into `RemoteBuildingSource.sheetUrl`:

```
https://docs.google.com/spreadsheets/d/e/2PACX-1vS9SjrzUVx7LWubKqj58JLw_jpgbutPT_EO-
UnOZWRryYBFPs8x77Pbxn8NftGWg49dQaF_Qnw9ZLcY/pub?gid=0&single=true&output=csv
```

### Columns

Parsed **by header name**, so column order never matters and new columns can be
appended safely.

| Column | Meaning |
|---|---|
| `id` | Permanent unique key. Discovery progress is saved against it — **never change it** |
| `status` | `published` or `draft`. Drafts are invisible unless developer mode is on |
| `name_en` / `name_bg` | Building name. Search matches either |
| `desc_en` / `desc_bg` | Description |
| `year` / `year_bg` | Display year, free text — "15th c." and "Unknown" are fine |
| `year_numeric` | Drives era filtering. `0`/blank means unknown era |
| `architect_en` / `architect_bg` | |
| `category` | Matched by name to a Category asset, case-insensitively |
| `lat` / `lng` | Marker position. Parsed with **invariant culture** |
| `link_en` / `link_bg` | External link. Empty means no Learn More button |
| `marker` | Optional style key override. Blank uses the category's |
| `marker_colour` | Optional hex like `#C2483A`. Blank uses the category's |

### Rules that matter

- **A row is skipped entirely** if it has no `id` or no usable coordinates.
- **Empty Bulgarian falls back to English.** `BuildingData.Pick()` only uses a
  Bulgarian field when Bulgarian is selected *and* that field is non-empty.
- **Coordinates parse as invariant culture.** On a phone set to Bulgarian, current
  culture reads `.` as a thousands separator and turns `42.48` into `4248`.
- **Set the spreadsheet locale to United States** (`File → Settings → Locale`).
  A Bulgarian locale writes decimals with commas and destroys the CSV.
- Eight decimal places of coordinate precision is about one millimetre. Google Sheets
  trimming longer values is harmless — ARCore is accurate to metres.

### Loading

1. On `Start`, read the cached copy from `Application.persistentDataPath/buildings.csv`
   and publish it immediately, so the app is usable in the first second.
2. Fetch the URL. On success, publish and overwrite the cache.
3. On failure, stay silent and keep whatever was already loaded. Only a first run with
   no cache *and* no network shows "Couldn't load buildings."
4. Refetch when the app returns from the background, rate-limited to once per
   30 seconds.

A published sheet that has been unshared returns an HTML error page with HTTP 200, so
the response is checked for a leading `<` before it is trusted.

## 7. The AR pipeline

### Position: two tiers

`UserLocationService` reports a position from one of two sources, and they are not
interchangeable.

| | Source | Accuracy | Heading | Used for |
|---|---|---|---|---|
| **Geospatial** | ARCore's fusion of GNSS, IMU, compass, VIO and VPS | sub-metre once VPS localizes | yes, with `OrientationYawAccuracy` | markers, and everything else |
| **GPS** | Unity's `Input.location` | 5–20 m | **none** | lists, distances, counts only |

Geospatial is tried first every poll; GPS is a floor, not a supplement. Averaging the
two would mean second-guessing Kalman-grade sensor fusion with a raw fix.

**Markers gate on `HasPrecisePose`, never `HasValidPose`.** Position error is
survivable; heading error is not. At 100 m a 15° heading error — routine for a
magnetometer near buildings — puts a marker 27 m sideways, a whole building off. GPS
supplies no heading at all, so it can never place anything in the world.

On the GPS tier, `HorizontalAccuracy` reports the GPS figure, so `VpsStatus` reads
`Unavailable`, the dot stays blue, and **Start stays disabled**. The app stops being
blind indoors and at night without ever pretending to be calibrated. Distances derived
from GPS are prefixed `~`.

`CheckVpsAvailabilityAsync` runs as soon as any position is known — including a GPS
one — so the Ready State can say "no visual positioning here" instead of coaching
someone forever to point at facades that will never help.

**What this does not fix:** AR markers indoors or after dark. That is a hard
constraint, not a bug. One nuance worth knowing: once VPS has localized, VIO carries
the pose forward even as VPS stops matching — so localizing in a lit spot and then
walking into a darker street keeps markers working.

### Marker spawning

`MarkerSpawner` runs on the location service's once-a-second cadence:

- Buildings within **500 m** get a marker; markers are released past **650 m**. The
  gap stops them flickering when you stand near the boundary.
- At most **20 markers** at once, nearest first. ARCore only tracks a bounded number
  of anchors well.
- Each is a **terrain anchor at 1.5 m above ground** —
  `ResolveAnchorOnTerrainAsync(lat, lng, 1.5, identity)`. ARCore resolves the height
  against real ground, so **no building carries an altitude**. This removed the single
  most error-prone number in the old workflow.
- Resolution failure is expected, not exceptional — it fails indoors, in poor VPS
  coverage, and before Earth tracking settles. The next sync retries.
- The marker is parented under the resolved anchor and given a `TappableObject`
  carrying its `BuildingData`, which is why the existing tap handling works unchanged.

### Marker appearance

Resolution order, checked in turn:

```
building.markerStyle   (the sheet's "marker" column)
  ↓ else
category.markerStyle
  ↓ else
spawner.defaultPrefab   ← currently a cube
```

Colour resolves the same way, sheet first. This means **colour-coded classification
works today on plain cubes**, from hex values typed into the sheet, with no marker art.

`MarkerView` handles per-marker behaviour: fixed world size that stops shrinking past
60 m so distant markers stay visible and tappable, optional billboarding, and tinting
through a `MaterialPropertyBlock` so a hundred markers still share one material.

### Occlusion

Two mechanisms, because neither covers the whole range:

- **Streetscape Geometry** — Google's building meshes become invisible `MeshCollider`s
  on Unity's built-in *Ignore Raycast* layer. A raycast runs camera→marker; if it
  crosses a building, the whole marker is hidden, renderer **and** collider. This is
  what stops a marker on a far street showing through the block in front of you.
- **Depth API** — `AROcclusionManager` occludes per-pixel through the AR background
  shader, covering cars, walls and people. ARCore's depth is only dependable to about
  8 m, so it cannot do the job above.

Depth is deliberately **not sampled per marker** — that would mean a CPU image read
every frame to solve a case that resolves itself the moment you take a step.

**The detail that would otherwise break it:** a marker sits at its own building's
coordinates, so that building's mesh is between you and its marker. The raycast stops
**5 metres short** (`surfaceToleranceMetres`), so a facade at 48 m does not hide a
marker at 50 m, while a building at 20 m does hide a marker at 200 m.

Occlusion **fails open** — no service, no camera, no meshes, or the setting off, and
nothing is ever hidden. A missing mesh must never make markers disappear.

## 8. The interface

Three tabs, driven by `TabNavigationController`. Canvas is Screen Space – Overlay,
Scale With Screen Size, reference resolution **1080 × 1920**.

### Camera tab — two states

**Ready State** (`ReadyStateView`) is a full-bleed opaque panel shown on cold launch.
It exists because ARCore needs several seconds to localize, during which markers are
absent or visibly wrong — indistinguishable from a broken app, at exactly the moment
someone decides whether it works.

It shows a time-of-day greeting, `"{n} buildings around you"`, the three nearest
buildings, and a calibration card that tracks `VpsStatus` live. **Start** unlocks at
`Fair`. **Start anyway** is live at every state, so nobody is ever trapped by a VPS
state that will not resolve. The bottom nav hides here, because the buttons occupy
that space.

It appears **once per session** — returning from Search goes straight to Live.
Backgrounding for over 120 seconds resets it.

**Live view** (`LiveARView`) holds the nearby-count pill, the calibration dot with its
explainer bubble, the Nearby sheet, the info sheet, and a warning banner shown only
when Live was entered via "Start anyway".

Crucially, **the AR session is never disabled.** Turning it off would stop Geospatial
localization — the exact thing the Ready State waits for. The session runs from launch
and the Ready State simply covers the feed with an opaque panel; tap input is gated on
`LiveARView` being active.

### Search tab

Search field, then **era and type filter pills that are always visible**. Filters are
multi-select and combine **OR within a dimension, AND across them** — "Civic or
Religious, from the Socialist or Transition era" is expressible. Tapping an active
pill clears it.

Below that, either browse content (suggestions, discovery card) or results. Tapping a
result switches to the Camera tab, enters Live, and opens the sheet — in that order,
because the sheet lives inside that tab and cannot render while it is inactive.

**This tab never needs an AR pose.** Distances appear when one is available and are
omitted otherwise, so it works indoors and before calibration.

### Settings tab

Appearance (dark mode, hide markers behind buildings), Language (EN/BG segmented),
Notifications (preference only — no scheduling built), Help (three sub-pages with a
working back button), and a version footer.

**Seven taps on the version number** toggles developer mode, which reveals draft
buildings. The label then reads `Version 0.1.0 · dev`.

### Theming

Every colour comes from `AppTheme` through a `ThemeRole`. Elements carry a
`ThemedElement` naming their role, and the light/dark switch recolours all of them at
once. **Nothing may hardcode a colour** — anything that does is stranded in the wrong
theme. Elements whose colour depends on state (filter pills, switch tracks, the
language segment) deliberately have no `ThemedElement`, because the two would fight.

Shapes come from three generated 9-sliced sprites in `Assets/UI/` — rounded, pill and
circle. Unity's default UI sprite is a hard rectangle, which is the single biggest
reason a built screen looks nothing like its mockup.

### Localization

`AppStrings` holds every user-facing string in both languages, keyed by name. It is a
deliberate stand-in for Unity Localization: when that package is installed, `Get()`
becomes a one-line wrapper over a string table and the dictionaries are deleted —
nothing that calls it has to change.

Building content is **not** in string tables. It uses parallel `_bg` fields on
`BuildingData` and the sheet — see §11 for why.

Distance formatting is locale-aware beyond the suffix: Bulgarian uses a comma as the
decimal separator, so `1.2 km` becomes `1,2 км`.

## 10. Editor tooling

All under `Tools/` in the menu bar.

| Command | What it does |
|---|---|
| **UI → Lay Out App UI** | Sets anchors, sizes and base geometry on the existing Canvas. Creates and deletes nothing |
| **UI → Build App UI** | Builds and wires the entire interface, services, spawner and occlusion. **Safe to re-run** |
| **Building Data → Create Starter Categories and Eras** | Generates the 8 categories and 4 eras. Never overwrites |
| **Building Data → Sync Coordinates From Anchors** | **Obsolete.** No hand-placed anchors remain |
| **Building Data → Validate All Buildings** | **Obsolete.** Validates the dead `Resources` assets, not the sheet |
| **Building Data → Create Tap Test Scene** | Generates a non-AR scene to verify the tap chain in the Editor |

### About `Build App UI`

It destroys everything it owns before rebuilding, so the whole run is wrapped in a
try/catch that calls `Undo.RevertAllDownToGroup` on failure. An early version without
that guard threw partway and left the scene gutted three times in a row.

It also **rescues `InfoPanel`** — a scene object that lives inside the generated
`LiveARView` — back out to `CameraPanel` before deleting that wrapper, or a rebuild
would take the panel and all its Inspector wiring with it.

Supporting files: `UIFactory.cs` (construction helpers that enforce theming and
shapes), `UISprites.cs` (generates the rounded/pill/circle PNGs on first run).

## 11. Decisions and why

**Content in a Google Sheet, not the binary.** Three new buildings used to cost a scene
edit, a rebuild, an upload and 1–3 days of Play review. Now they cost three rows.

**Markers spawned at runtime, not placed in the Editor.** Removes ~2 minutes of
mechanical work per building, makes remote content actually reach the AR view, and
removes the need for the regional additive scene loading that was previously planned.

**Terrain anchors, not WGS84.** WGS84 needs an absolute ellipsoidal altitude, which
differs from sea level by roughly 35 m in Bulgaria and is unknowable per building
without survey data. Terrain anchors resolve against real ground. This was the cause
of at least one failed field test.

**Parallel `_bg` fields, not Localization string tables, for building content.**
Originally the opposite was chosen. It was reversed because: `AppStrings` already does
key→(EN,BG) without the package; categories and eras were already on parallel fields
and worked; and the main advantage of string tables — letting a translator work
without touching assets — does not apply to a solo developer with no translator.
A GUID-based key was also rejected: readable ids keep the data legible.

**`AppStrings` instead of Unity Localization for UI chrome.** Same reasoning, plus it
works today. The migration path is deliberately one function wide.

**Legacy `Input` for tap detection.** Settled after extensive debugging. `Active Input
Handling` is `Both` and must stay. Do not migrate 3D object picking to the new Input
System.

**The AR session is never paused.** See §8.

**Occlusion fails open.** A missing mesh must never make markers vanish.

**`status` column with a draft state.** Lets coordinates be captured on site weeks
before the description is written, without a nameless marker appearing meanwhile.

**No `has_link` column.** An empty `link_en` cell is already the "no". A yes/no column
would be a second source of truth that can disagree with reality.

## 12. Bugs already fixed

Recorded so they are not re-diagnosed.

| Symptom | Cause | Fix |
|---|---|---|
| Shader "out of memory" on Android build | `CesiumDefaultTilesetShader` generating ~36 billion variants | Reassign Opaque Material to `CesiumUnlitTilesetMaterial`; tag `Cesium3DTileset` **EditorOnly** |
| Yellow screen on device | URP Renderer missing **AR Background Renderer Feature** | Added to both renderers |
| `CS0234` InputSystem namespace | Package cache corruption after an Editor crash | Delete `Library/PackageCache` only |
| Gradle `DirectoryNotFoundException` | EDM4U copying into a missing folder | Create `Assets/Plugins/Android` |

| Editor crash on exiting Play | Custom `FlowLayoutGroup` reading destroyed children during teardown | Null-check children; pills measure themselves instead of nesting fitters |

| Search results did nothing | `Action<T>` is not serializable, so the builder's edit-time assignment was discarded | Serialized `tabs` / `cameraTab` references, wired at runtime |
| Sections overlapping | `ContentSizeFitter` on children of a `VerticalLayoutGroup` — both driving the same rect | Fitters only on scroll content and free-floating elements |
| Light mode half-applied | `Lay Out App UI` painted the shell with fixed colours from before the theme system | Shell now carries `ThemedElement` |
| Close buttons drawn as boxes | `✕` and `❚` are not in the Latin-only font atlas | Crosses drawn from two rotated bars |
| `21 Ð¼` instead of `21 м` | One string double-encoded (UTF-8 bytes read as Latin-1) by a repair script whose range stopped one line short | Rewritten; whole project scanned, clean |

## 13. Known issues

### Blocking
- **Bundle ID is still the URP template default**:
  `com.UnityTechnologies.com.unity.template.urpblank`. Permanent once published, so it
  must be changed before the first upload.

### Unverified, not blocking
- **Streetscape Geometry coverage in Yambol.** It needs Google's 3D building data,
  which is thorough in large cities and patchy in small towns. To check: tick
  **Show Occluders** on `OcclusionService` (on `AppServices`) and build. Mesh shells
  over the surrounding buildings mean coverage is good; a normal-looking screen means
  there is none, and only the near-range depth occlusion does anything. Occlusion
  fails open, so no coverage breaks nothing.

### Corrections to earlier belief
- **Cyrillic was never broken.** It was repeatedly called a blocker. In fact
  `LiberationSans SDF` has a **dynamic fallback** font asset that rasterizes missing
  glyphs on demand from Liberation Sans, which contains Cyrillic. No font work was
  ever needed, and the phone renders Bulgarian correctly today.

### Fragile
- **Cesium is installed from a tarball on the Desktop**
  (`file:C:/Users/zalex/Desktop/com.cesium.unity-1.19.0.tgz`). Move or delete that file
  and the project stops resolving. Move it inside the project.
- **ARCore Extensions is pinned to a git branch**, not a release tag.
  `packages-lock.json` holds the current commit, but a re-resolve can pull a different
  version silently.
- **The ARCore API key sits in plain text** in
  `ProjectSettings/ARCoreExtensionsProjectSettings.json`. It ships in the APK
  regardless — that is normal — but restrict it in Google Cloud Console to the ARCore
  API and the app's package name plus signing SHA-1 once the bundle id is real.

### Dead weight
- `Assets/Resources/BuildingData/` holds two legacy assets nothing loads.
- `Sync Coordinates From Anchors` and `Validate All Buildings` operate on assets and
  anchors that no longer drive anything.
- `GeospatialDebugOverlay` should be disabled for release.
- `StreetscapeGeometryMode` is still `0` in the config; the next `Build App UI` sets it.

## 14. Building and publishing

- **Android wants an AAB**, not an APK. Play has required app bundles for new apps
  since 2021. APKs are fine for sideloading to your own phone.
- **iOS needs a Mac.** Unity generates an Xcode project that must be compiled on
  macOS. A cloud Mac service works.
- **Costs**: Play Console $25 once, Apple Developer Program $99 every year.
- **The signing keystore is the one irreversible mistake.** Lose the file or its
  password and this app can never be updated by anyone, ever. Back it up to two places
  the day it is created.
- A **privacy policy is mandatory** — the app requests camera and location.
- Complete Play's **Data Safety** form: location is used for positioning, nothing is
  stored off-device.
- Ship to the **internal testing track** first.

Current settings: `bundleVersion 0.1.0`, `minSdkVersion 29`, `targetSdkVersion`
Automatic.
